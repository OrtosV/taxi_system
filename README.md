# Интеллектуальная система прогнозирования спроса на поездки такси

**Разработка интеллектуальной прогнозно-аналитической системы прогнозирования пространственно-временного спроса на поездки такси с учётом внешних факторов**

## 1. Описание проекта

Проект представляет собой интеллектуальную прогнозно-аналитическую систему, предназначенную для прогнозирования количества поездок такси по географическим зонам Нью-Йорка с горизонтом прогнозирования один час.

Система объединяет исторические данные о поездках, погодные условия, информацию о дорожно-транспортных происшествиях и обращения жителей в городскую службу 311. На основе объединённого набора данных формируется пространство признаков, после чего обучаются и сравниваются модели машинного обучения.

Результаты прогнозирования отображаются в интерактивном веб-интерфейсе. Пользователь может выбирать дату и время, изучать пространственное распределение ожидаемого спроса, анализировать динамику отдельных зон и оценивать изменение прогноза при различных погодных условиях.

**Основной пользователь системы:** аналитик транспортных операций или специалист по распределению парка такси.

**Практическая задача:** определение зон с ожидаемым повышенным спросом для поддержки решений о распределении транспортных ресурсов.

## 2. Цель и задачи проекта

**Цель:** разработать воспроизводимую интеллектуальную систему прогнозирования пространственно-временного спроса на поездки такси с использованием методов машинного обучения и внешних данных.

Для достижения цели решаются следующие задачи:

- организация загрузки данных из нескольких разнородных источников;
- формирование единого исторического набора данных;
- очистка, проверка качества и пространственно-временное объединение данных;
- построение признакового пространства для прогнозирования;
- обучение и сравнение моделей машинного обучения;
- выбор итоговой модели по результатам временной валидации и тестирования;
- интерпретация прогнозов и анализ значимости признаков;
- разработка механизмов мониторинга качества и управления версиями моделей;
- создание интерактивного аналитического интерфейса.

## 5. Формирование целевой переменной

В качестве целевой переменной используется количество поездок такси, начинающихся в определённой географической зоне в течение одного часа.

Обозначим целевую переменную:

\[
y_{z,t} = \operatorname{count}(z,t),
\]

где:

- \(z\) — географическая зона Нью-Йорка;
- \(t\) — временной интервал продолжительностью один час;
- \(y_{z,t}\) — количество поездок, начавшихся в зоне \(z\) за час \(t\).

Задача модели — спрогнозировать спрос на следующий час:

\[
\hat{y}_{z,t+1} = f(X_{z,t}),
\]

где \(X_{z,t}\) — признаки, доступные на момент формирования прогноза.

После агрегации исторических поездок сформирована полная временная сетка:

- 263 географические зоны;
- 17 544 временных интервала;
- 4 614 072 наблюдения.

Специальные зоны `Unknown` и `Outside of NYC` сохраняются в исторических данных и модельном наборе, но исключаются из географической визуализации. На карте отображаются 261 зона с соответствующей геометрией.

## 6. Предобработка и формирование признаков

После загрузки источников выполняется проверка структуры данных, типов полей, пропусков, дубликатов и корректности временных отметок.

Далее данные объединяются по временным интервалам и географическим зонам.

Для модели сформировано 47 признаков, которые можно разделить на несколько групп.

### Временные признаки

- час прогнозируемого интервала;
- день недели;
- день месяца;
- месяц;
- признак выходного дня;
- циклические представления часа и дня недели через синус и косинус.

### Исторический спрос

Используются лаговые признаки:

- спрос за предыдущий час;
- спрос 2, 3 и 6 часов назад;
- спрос 24, 48 и 168 часов назад.

Дополнительно рассчитываются скользящие статистики:

- средний спрос за 3, 6, 24 и 168 часов;
- стандартное отклонение спроса за 24 и 168 часов.

### Погодные признаки

- температура воздуха;
- относительная влажность;
- количество осадков;
- скорость ветра;
- код погодного явления;
- признак доступности погодных данных.

### Дорожная обстановка

Используются сведения о количестве ДТП, пострадавших и погибших, в том числе с разделением по категориям участников дорожного движения.

### Городская активность

Из обращений 311 формируются признаки:

- общее количество обращений;
- обращения, связанные с дорожным движением;
- обращения по состоянию дорог;
- обращения, связанные с городской активностью;
- обращения, связанные с жилой средой;
- количество обращений с описанием.

### Пространственные признаки

- идентификатор зоны;
- боро;
- название зоны;
- тип обслуживаемой зоны.

**Предотвращение утечки данных.** Исторические и внешние признаки сдвигаются относительно прогнозируемого интервала. Для формирования прогноза используются только сведения, доступные на момент его построения. Временные календарные признаки рассчитываются непосредственно для прогнозируемого часа.

### Разделение данных

Использовано хронологическое разделение без случайного перемешивания наблюдений:

## 7. Обучение и сравнение моделей

Для решения задачи были рассмотрены модели различных классов:

1. Seasonal Naive — базовая модель, использующая значение спроса за аналогичный час предыдущего дня.
2. Random Forest — ансамбль деревьев решений на основе бэггинга.
3. XGBoost — алгоритм градиентного бустинга над деревьями решений.
4. LightGBM — реализация градиентного бустинга с оптимизированным построением деревьев.
5. CatBoost — алгоритм градиентного бустинга с поддержкой категориальных признаков.

Для каждой модели использовались одинаковые целевая переменная, набор признаков и временные выборки. Для моделей выполнялась настройка гиперпараметров с ограниченным бюджетом экспериментов.

### Метрики качества

Для оценки использовались пять метрик:

- **MAE** — средняя абсолютная ошибка прогноза.
- **MSE** — средняя квадратичная ошибка.
- **RMSE** — корень из средней квадратичной ошибки.
- **WAPE** — взвешенная абсолютная процентная ошибка.
- **R²** — коэффициент детерминации.

### Сравнение моделей на Test

| Модель | MAE | RMSE | WAPE, % | R² |
|---|---:|---:|---:|---:|
| Seasonal Naive | 6.8421 | 23.5589 | 30.6566 | 0.8585 |
| Random Forest | 4.9278 | 15.2141 | 22.0792 | 0.9410 |
| Random Forest Tuned | 4.3866 | 13.1465 | 19.6546 | 0.9559 |
| XGBoost | **4.2014** | **11.9203** | **18.8247** | **0.9638** |
| XGBoost Tuned | 4.3224 | 13.1315 | 19.3670 | 0.9560 |
| LightGBM | 4.6874 | 13.0916 | 21.0023 | 0.9563 |
| LightGBM Tuned | 4.5366 | 13.4610 | 20.3267 | 0.9538 |
| CatBoost | 4.6166 | 13.1369 | 20.6848 | 0.9560 |
| CatBoost Tuned | 4.3525 | 12.3179 | 19.5018 | 0.9613 |

Итоговой моделью выбрана исходная конфигурация XGBoost.

Её результаты на тестовой выборке:

- MAE: 4.2014;
- MSE: 142.0940;
- RMSE: 11.9203;
- WAPE: 18.8247%;
- R²: 0.9638.

По сравнению с Seasonal Naive итоговая модель снизила MAE приблизительно на 38,6%.

Примечательно, что настроенная версия XGBoost показала лучшие результаты на Validation, но уступила исходной конфигурации на Test. Поэтому для дальнейшего использования была выбрана исходная модель, показавшая более высокое качество на тестовой выборке.

**Ограничение эксперимента:** тестовая выборка использовалась при сравнении моделей и выборе итоговой конфигурации. Поэтому её нельзя считать полностью независимой, ранее не использованной контрольной выборкой.

## 8. Интерпретация модели

Для анализа поведения итоговой модели XGBoost использованы два независимых подхода:

- Permutation Importance;
- SHAP (SHapley Additive exPlanations).

Permutation Importance позволяет оценить снижение качества модели при случайном перемешивании значений отдельного признака.

SHAP используется для оценки вклада признаков в отдельные прогнозы и анализа глобальной значимости признаков.

Наиболее значимыми факторами по результатам анализа стали:

- идентификатор географической зоны;
- спрос за 168 часов;
- спрос за предыдущий час;
- название зоны;
- спрос за 24 часа;
- спрос за 6 часов;
- временные признаки прогнозируемого интервала.

Дополнительно выполнены:

- построение локального объяснения отдельного прогноза;
- анализ зависимости SHAP-значений от значений признаков;
- сравнение значимости признаков между двумя последовательными периодами Validation.

Результаты показали, что структура наиболее значимых факторов в рассмотренных периодах в целом сохраняется.

Следует учитывать, что SHAP и Permutation Importance описывают поведение модели, но сами по себе не устанавливают причинно-следственные связи между признаками и спросом.

## 9. Мониторинг и управление версиями моделей

В проекте реализованы механизмы демонстрационного мониторинга и управления жизненным циклом моделей.

### Data Drift

Для контроля изменения распределений признаков используется Population Stability Index (PSI).

В мониторинг включены шесть признаков:

- спрос за предыдущий час;
- спрос за 168 часов;
- температура;
- осадки;
- скорость ветра;
- количество обращений 311.

Для демонстрации обнаружения дрейфа создаётся искусственно смещённый набор признаков, после чего его распределение сравнивается с исходным.

### Performance Drift

Качество рабочей модели оценивается по месячным показателям Validation. Рассчитываются MAE, MSE, RMSE, WAPE и R².

В качестве демонстрационного правила переобучения используется превышение пороговых значений MAE или WAPE на двух последовательных периодах.

### Реестр моделей

Для управления версиями используется реестр, содержащий:

- номер версии;
- идентификатор эксперимента;
- название модели;
- путь к артефакту;
- набор признаков;
- гиперпараметры;
- метрики Validation;
- статус версии;
- историю операций.

Продвижение кандидата выполняется при улучшении MAE и WAPE на Validation относительно текущей модели. При ухудшении контрольных метрик предусмотрен механизм отката к предыдущей версии.

### Демонстрационный сценарий

В интерфейсе реализована кнопка «Проверить актуальность модели».

При её нажатии выполняется следующий сценарий:

1. Создание искусственно смещённого набора признаков.
2. Расчёт PSI и выявление признаков с изменившимся распределением.
3. Расчёт месячных метрик качества на исторической Validation.
4. Проверка кандидата XGBoost Tuned на Validation.
5. Демонстрационное продвижение кандидата версии 1.2.0.
6. Сравнение Test-метрик кандидата и исходной модели.
7. Откат к исходной версии 1.0.0, поскольку кандидат уступил ей на Test по MAE и WAPE.
8. Сохранение отчёта и истории демонстрационного запуска.

**Важно:** это демонстрация механизма мониторинга на исторических и искусственно смещённых данных, а не полноценный онлайн-мониторинг поступающих пользовательских данных. Демонстрационный реестр хранится отдельно и не изменяет рабочий реестр моделей приложения.

## 10. Интерактивный аналитический интерфейс

Для визуализации результатов разработано веб-приложение на Streamlit.

Основные возможности интерфейса:

- выбор даты и часа прогнозирования;
- отображение суммарного прогнозируемого спроса;
- интерактивная карта Нью-Йорка с распределением спроса по географическим зонам;
- выбор отдельной зоны для просмотра подробной информации;
- график фактического спроса за предыдущие 24 часа и прогноза на выбранный час;
- отображение топ-10 зон с наибольшим ожидаемым спросом;
- изменение погодных условий и пересчёт прогноза;
- сравнение базового и сценарного прогнозов по всем отображаемым зонам;
- просмотр информации о рабочей модели и её метриках;
- запуск демонстрационной проверки актуальности модели.

Для карты используется Folium, для графиков — Plotly, для веб-интерфейса — Streamlit.

Погодный сценарий позволяет оценить реакцию модели на замену погодных входных признаков. Полученное изменение прогноза не является оценкой причинного влияния погоды на спрос.

## 14. Ограничения и направления развития

Текущая реализация представляет собой исследовательский прототип прогнозно-аналитической системы.

Основные ограничения:

- прогнозирование основано на исторических данных за 2024–2025 годы;
- интерфейс позволяет выбирать исторические временные срезы, для которых доступны подготовленные признаки;
- демонстрационный мониторинг использует искусственно смещённые признаки и исторические метрики;
- погодные сценарии заменяют погодные входные признаки модели и не являются причинным анализом;
- временные отметки исходных данных представлены в локальном времени Нью-Йорка, поэтому переходы на летнее и зимнее время требуют отдельного внимания при дальнейшем развитии системы.

В качестве направлений развития можно выделить:

- организацию регулярной автоматической загрузки новых данных;
- подключение погодного прогноза для будущих временных интервалов;
- реализацию полноценного мониторинга на новых поступающих данных;
- автоматизацию переобучения и проверки кандидатов;
- расширение географического и временного горизонта прогнозирования;
- внедрение механизма планирования распределения парка такси.

## 15. Итог

В рамках проекта разработан прототип интеллектуальной прогнозно-аналитической системы, охватывающий полный цикл работы с данными: от загрузки и подготовки разнородных источников до обучения, оценки, интерпретации и визуализации результатов прогнозирования.

Выполнено сравнение нескольких алгоритмов машинного обучения, выбрана итоговая модель XGBoost, реализованы методы интерпретации и демонстрационный механизм мониторинга с управлением версиями моделей.

Разработанный интерфейс обеспечивает пространственный анализ прогнозируемого спроса, исследование отдельных зон и сравнение погодных сценариев, позволяя использовать результаты модели для поддержки решений по распределению транспортных ресурсов.
